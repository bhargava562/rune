## The Problem

Every AI coding tool needs its own config file to understand how you work.

| Tool | Config File |
|---|---|
| Claude Code | `CLAUDE.md` |
| GitHub Copilot | `.github/copilot-instructions.md` |
| Cursor | `.cursor/rules/*.mdc` |
| Google Antigravity | `GEMINI.md` |
| Kiro | `.kiro/steering/*.md` |
| OpenCode | `~/.config/opencode/AGENTS.md` |

Without these files, every tool starts blank — no style, no opinions, no memory of how your team works. Setting them up manually takes hours. And they drift apart the moment your stack changes.

**`rune` generates all of them from one source of truth. In one command.**

## Quick Start

There are two ways to use `rune`:

### Option A: The "Zero-Install" Run (Best for quick usage)
Run `rune` directly from GitHub into your current project folder using a single curl command.

```bash
# Run rune in your current project directory
bash <(curl -fsSL https://raw.githubusercontent.com/bhargava562/rune/main/scripts/setup.sh)
```

### Option B: The Global CLI Installation (Best for long-term use)
To make it work exactly like a standalone package (where you just type `rune` in any terminal):

```bash
# Install rune globally
curl -fsSL https://raw.githubusercontent.com/bhargava562/rune/main/install.sh | bash
```

Once installed, simply `cd` into any of your projects and type:
```bash
rune
```

Pick your tools. `rune` fetches the templates dynamically from GitHub and generates the correct config file for each one — pre-loaded with senior engineer defaults.

## What You Get Out of the Box

Every AI tool you configure through `rune` gets:

**Senior engineer persona** — direct communication, no filler phrases, production-quality bar by default.

**Behavior rules** — plan before coding, explain before acting, never delete code without explicit confirmation, always read files before assuming.

**Tool-specific instructions** — each tool gets rules tuned to how it actually works internally, not generic advice.

## Extend Without Touching Core Files

Need stack-specific rules? Drop a `.md` file into `extensions/`:

```
extensions/
└── python.md
```

```markdown
Always use async functions.
Use snake_case. Never use print() — use logging.
```

Run `setup.sh` again. Your rules merge on top. Core files stay untouched.
Works for any stack, any team convention.

## How It Works

```
rune/
├── templates/              ← source of truth (committed to git)
│   ├── AGENTS.md           ← base behavior rules
│   ├── persona.md          ← communication style
│   └── adapters/
│       ├── claude.md       ← claude-specific additions
│       ├── copilot.md
│       ├── cursor.md
│       ├── antigravity.md
│       ├── kiro.md
│       └── opencode.md
│
├── extensions/             ← your custom rules (gitignored)
│   └── python.md
│
├── core/                   ← generated by setup.sh (gitignored)
│
└── scripts/
    └── setup.sh            ← the only entry point
```

The `rune` script fetches templates dynamically from the `templates/` directory on GitHub, merges your local `extensions/` (if any) on top, and writes the correctly formatted file for each selected tool into your current working directory. There is no need to clone this repository locally!

## Add a New Tool

Extending `rune` for any new AI assistant takes under a minute:

1. Create `templates/adapters/newtool.md` with tool-specific instructions
2. Add a `case` block in `scripts/setup.sh` with the output file path
3. Run `setup.sh`

No other files change.
